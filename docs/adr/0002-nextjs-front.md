Utiliser Next.js pour le développement front-end (BFF & UI)Statut : acceptéeDate : 2026-11-10Décideurs : l'équipe Front & TechContextePour le Challenge Sales de Givaudan, l'interface utilisateur doit convaincre le jury à travers une expérience fluide, percutante et haut de gamme. Le délai de réalisation est extrêmement court (deux semaines). L'application doit être entièrement conteneurisée via Docker et capable de récupérer de manière centralisée les appels API (exposés notamment via ngrok pour les démos en ligne). De plus, pour valoriser le parcours de vente et l'IA, le front-end nécessite une grande liberté d'intégration pour des animations graphiques avancées (GSAP, Anime.js, etc.). OptionsNext.js : Framework React proposant une architecture Back-End for Front-End (BFF) intégrée. Il permet de centraliser et sécuriser les appels API, de simplifier le déploiement dans notre conteneur Docker, tout en conservant toute la flexibilité de React pour orchestrer des bibliothèques d'animation complexes (GSAP, Anime.js). React (Vite SPA) : Application monopage classique. Bien qu'elle gère bien les animations, elle oblige à configurer manuellement un routeur, des proxys pour les appels API et complexifie la gestion des flux asynchrones, ce qui fait perdre un temps précieux sur un sprint de deux semaines.HTML/CSS/JS Vanilla : Absence de framework. Le développement d'une interface de vente riche et interactive avec des animations poussées deviendrait rapidement non maintenable dans le délai imparti.DécisionNous choisissons Next.js parce que son architecture BFF intégrée nous fait gagner un temps critique sur les deux semaines, simplifie la gestion centralisée des appels API (vers ngrok/FastAPI), s'intègre proprement dans notre conteneur Docker, tout en nous offrant une totale liberté pour concevoir des animations fluides et engageantes (GSAP, Anime.js). ConséquencesPositives : Gain de temps majeur grâce au BFF pour router et centraliser les appels API ; conteneurisation Docker simplifiée ; flexibilité totale de l'écosystème React pour des animations de vente percutantes (GSAP, Anime.js). Négatives, à accepter : Un écosystème globalement plus lourd qu'une simple SPA statique, nécessitant un runtime Node.js dans le conteneur.À revoir si : Le projet évolue vers une application purement mobile ou hors du web.
